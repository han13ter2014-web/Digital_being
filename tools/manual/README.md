# Ручные проверки

Скрипты в этой папке **не запускаются pytest** — у них нет утверждений
(`assert`) и они печатают результат в консоль. Это инструменты для
ручной проверки поведения, когда нужно посмотреть на живой вывод.

Запуск (из корня проекта):

```bash
python tools/manual/synthesis_manual.py
python tools/manual/new_systems_manual.py
python tools/manual/checkpoint_restore_manual.py
python tools/manual/death_risk_driven_manual.py
python tools/manual/motivation_measure.py 200
python tools/manual/body_calibration.py
python tools/manual/memory_maturity_measure.py 300 --hold-energy --seed 1
python tools/manual/loop_accounting_measure.py 200 --hold-energy --seed 1
```

`motivation_measure.py` — замер мотивации, тела и памяти через настоящий
раннер: кто предлагает действия (потребности, драйвы, Active Inference),
что выбрал арбитр, чем это кончилось, как менялись энергия, усталость и
АТФ, и что осталось в графе знаний (концепции, формулировки, связи,
консолидации). Данные пишутся во временную папку, сеть выключена. Флаги:

* `--hold-energy` — держать энергию на максимуме, чтобы изолировать
  мотивацию от телесной экономики;
* `--hungry` — начать с неудовлетворённых любопытства и связи;
* `--exhausted` — начать с нулевой энергии и высокой усталости
  (проверка выхода из истощения);
* `--no-consolidation` — контрольная группа: тот же код, но сон не
  осмысляет накопленное (сравнение «со сном / без сна»);
* `--report PATH` — записать отчёт в UTF-8 (консоль Windows искажает
  кириллицу);
* `--seconds-per-cycle N` — сколько «живых» секунд проживает цикл
  (по умолчанию 5, как в режиме live).

Без флагов каждый цикл «проживает» 5 секунд, и энергия восстанавливается
как в live.

`body_calibration.py` — траектории интероцептивной модели без агента:
покой, работа, отдых после работы, выход из полного истощения. Нужен,
чтобы подбирать числа модели (скорость утомления и восстановления) по
видимой кривой, а не на глаз.

`memory_maturity_measure.py` — замер зрелости памяти: сколько своих
концепций (без родовых) имеют формулировку, о скольких агент может
ответить и о скольких отвечает из памяти. Сравнивает прогон со сном и
без сна; `--seed N` фиксирует зерно случайности, иначе два прогона —
разные траектории и разницу нельзя приписать консолидации.

`loop_accounting_measure.py` — замер бухгалтерии петли: сколько действий
дают наблюдаемый результат, какие действия агент перестал выбирать и
почему (отказ тела или «выполнял, мир не менялся»), и как считается доля
результативности. Печатает два числа: по продуктивным действиям (как
считается теперь) и по всем (как считалось раньше, включая отдых и
отказы). `--seed N` нужен, чтобы «до/после» сравнивалось на одной
траектории.

Автоматические тесты живут в `tests/` и запускаются так:

```bash
python -m pytest -q
```

## Почему они здесь

Раньше эти файлы лежали в корне проекта с именами `test_*.py`, хотя
тестами в понимании pytest не были. Pytest их не собирал
(`testpaths = ["tests"]`), но они создавали впечатление, что тестов
больше, чем есть. Имена изменены на `*_manual.py`, чтобы это было
очевидно.

Если какой-то из сценариев нужен в CI — его следует переписать с
`assert` и положить в `tests/`.
