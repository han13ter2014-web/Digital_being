# Ручные проверки

`activity_routes_measure.py --report PATH` — изолированные дефициты и
реальные маршруты кандидатов; без исполнения, сети и навязанных долей занятий.
[План и находки](../../docs/LIFE_V1_PLAN.md).

`new_evidence_measure.py --report PATH` — отсутствие источника, ответ по
другой теме и по нужной; настоящее принятие ответа без сети.
[Результаты и ограничения](../../docs/NEW_EVIDENCE_OPPORTUNITY.md).

`continuation_summary.py REPORT [REPORT ...]` — сводка естественных возвратов:
предложения, выбор, pending/satisfied и повторы в том же контексте.
[Результаты](../../docs/INTENTION_EVIDENCE.md).

`attention_measure.py --cycles 1000 --seed N --report PATH` — реальный
арбитраж внешнего/собственного внимания, счётчик act на тик и ожидание
вопросов. Офлайн, лабораторное время; качество ответов не оценивает.
[Результаты](../../docs/UNIFIED_LIFE_TICK.md).

`gui_lifecycle_measure.py --report PATH` (или `--tray`) — реальное окно с
автоматическим выходом и проверкой чекпоинта; отдельный временный профиль.
Открывает окно/иконку в текущем desktop, не проверяет установленный .exe.

`backup_life_measure.py --report PATH` — полный путь save → backup → restore
в новый профиль → запуск и следующее ожидание, JSON/SQLite × сон/бодрствование.

`profile_backup.py create SOURCE NEW_DESTINATION`, `verify BACKUP`,
`restore BACKUP NEW_PROFILE` — явная резервная копия с manifest и проверкой
SQLite. Перед create остановить приложение; restore не затирает старый профиль.
[Границы согласованности](../../docs/LIFE_CONTINUITY_CONTRACT.md).

Скрипты в этой папке **не запускаются pytest** — у них нет утверждений
(`assert`) и они печатают результат в консоль. Это инструменты для
ручной проверки поведения, когда нужно посмотреть на живой вывод.

Запуск (из корня проекта):

```bash
python tools/manual/synthesis_manual.py
python tools/manual/new_systems_manual.py
python tools/manual/checkpoint_restore_manual.py
python tools/manual/death_risk_driven_manual.py
python tools/manual/motivation_measure.py 200
python tools/manual/body_calibration.py
python tools/manual/memory_maturity_measure.py 300 --hold-energy --seed 1
python tools/manual/loop_accounting_measure.py 200 --hold-energy --seed 1
```

`motivation_measure.py` — замер мотивации, тела и памяти через настоящий
раннер: кто предлагает действия (потребности, драйвы, Active Inference),
что выбрал арбитр, чем это кончилось, как менялись энергия, усталость и
АТФ, и что осталось в графе знаний (концепции, формулировки, связи,
консолидации). Данные пишутся во временную папку, сеть выключена. Флаги:

* `--hold-energy` — держать энергию на максимуме, чтобы изолировать
  мотивацию от телесной экономики;
* `--hungry` — начать с неудовлетворённых любопытства и связи;
* `--exhausted` — начать с нулевой энергии и высокой усталости
  (проверка выхода из истощения);
* `--no-consolidation` — контрольная группа: тот же код, но сон не
  осмысляет накопленное (сравнение «со сном / без сна»);
* `--report PATH` — записать отчёт в UTF-8 (консоль Windows искажает
  кириллицу);
* `--seconds-per-cycle N` — сколько «живых» секунд проживает цикл
  (по умолчанию 5, как в режиме live).

Без флагов каждый цикл «проживает» 5 секунд, и энергия восстанавливается
как в live.

`body_calibration.py` — траектории интероцептивной модели без агента:
покой, работа, отдых после работы, выход из полного истощения. Нужен,
чтобы подбирать числа модели (скорость утомления и восстановления) по
видимой кривой, а не на глаз.

`memory_maturity_measure.py` — замер зрелости памяти: сколько своих
концепций (без родовых) имеют формулировку, о скольких агент может
ответить и о скольких отвечает из памяти. Сравнивает прогон со сном и
без сна; `--seed N` фиксирует зерно случайности, иначе два прогона —
разные траектории и разницу нельзя приписать консолидации.
Флаг `--depth N` задаёт долю углубления (0..1); отчёт разделяет количество
встреч и силу свидетельств: повторение вопроса не означает нового знания.

`depth_sweep_summary.py КАТАЛОГ` — сводка отчётов
`depth_<доля>_<зерно>.txt`. Проверяет одинаковые наборы зёрен, берёт число
своих концепций из последнего среза и рассчитывает долю по точным числам,
а не по округлённым процентам. Результат проверки гипотезы глубины:
[`docs/DEPTH_EXPERIMENT.md`](../../docs/DEPTH_EXPERIMENT.md).

`checkpoint_storage_measure.py --records 10000 --snapshots 20 --report PATH` —
размер и время JSON/SQLite на одинаковом растущем опыте.
`checkpoint_maintenance.py DATABASE --import-json FILE` — явный импорт без
удаления исходника; `--gc` — удаление недостижимых блоков.
[Формат и ограничения](../../docs/SQLITE_CHECKPOINTS.md).

`autonomous_life_measure.py --cycles 1000 --seed N --report PATH` — естественная
энергия, неподменённый арбитр, перезапуск посередине; источники выбора,
предложения проверок, целевые наблюдения и целостность восстановления.
Ускорение не ускоряет wall-clock кулдауны. [Результаты](../../docs/AUTONOMOUS_LIFE_EXPERIMENT.md).
Также сохраняет initial_sources, escape_transitions и escape_traces:
исходный выбор, причину тупика, замену и её исход.
[Диагностика](../../docs/LOOP_ESCAPE_DIAGNOSTICS.md).
`--no-continuation` отключает только кандидат возврата для контроля;
continuation_offers/choices/losses/traces показывают его естественную работу.
[Результаты](../../docs/INTENTION_CONTINUATION.md).
`--no-method-feedback` отключает только раннюю обратную связь для контроля
«до/после»; результаты: [METHOD_FEEDBACK.md](../../docs/METHOD_FEEDBACK.md).

`experiment_choice_measure.py --report PATH` — контролируемое сравнение
арбитража с предложением проверки и без него: слабое побуждение уступает,
сильное — нет. [EXPERIMENT_CHOICE.md](../../docs/EXPERIMENT_CHOICE.md).

`claim_measure.py --report PATH` — одно действие, два независимых вывода:
энергия не выросла, усталость снизилась; оба переживают обычный запуск.
Описание: [EMPIRICAL_CLAIMS.md](../../docs/EMPIRICAL_CLAIMS.md).

`restart_continuity_measure.py --report PATH` — обычный повторный запуск:
опыт через act(), сохранение раннером, восстановление через create_agent(),
сравнение памяти и следующего ожидания. Данные изолированы. Описание:
[RESTART_CONTINUITY.md](../../docs/RESTART_CONTINUITY.md).

`action_expectation_measure.py --report PATH` — проверка ожидания на
реальном отдыхе: предсказание до действия, численное наблюдение после,
контролируемое нарушение восстановления и пересмотр следующего ожидания.
Описание: [ACTION_EXPECTATIONS.md](../../docs/ACTION_EXPECTATIONS.md).

`experience_measure.py --report PATH` — контроль различения переживания,
гипотезы и свидетельства: неприятное наблюдение меняет уверенность и
кандидата исследования, повтор источника и сон не создают подтверждений.
Подробности и ограничения: [EXPERIENCE_EPISTEMICS.md](../../docs/EXPERIENCE_EPISTEMICS.md).

`loop_accounting_measure.py` — замер бухгалтерии петли: сколько действий
дают наблюдаемый результат, какие действия агент перестал выбирать и
почему (отказ тела или «выполнял, мир не менялся»), и как считается доля
результативности. Печатает два числа: по продуктивным действиям (как
считается теперь) и по всем (как считалось раньше, включая отдых и
отказы). `--seed N` нужен, чтобы «до/после» сравнивалось на одной
траектории.

Автоматические тесты живут в `tests/` и запускаются так:

```bash
python -m pytest -q
```

## Почему они здесь

Раньше эти файлы лежали в корне проекта с именами `test_*.py`, хотя
тестами в понимании pytest не были. Pytest их не собирал
(`testpaths = ["tests"]`), но они создавали впечатление, что тестов
больше, чем есть. Имена изменены на `*_manual.py`, чтобы это было
очевидно.

Если какой-то из сценариев нужен в CI — его следует переписать с
`assert` и положить в `tests/`.
