# Участие в разработке (Contributing)

Digital Being — эксперимент по наблюдаемой цифровой жизни. Проект делает
один человек с помощью AI-ассистентов, но правки приветствуются. Чтобы не
сломать то, что здесь принципиально, прочитайте этот файл перед первым
изменением.

## Архитектурные границы

Эти правила — не стилистика, а смысл проекта. Сдвигать их можно только
после отдельного обсуждения в issue, где объяснено, зачем граница должна
сдвинуться.

1. **Без LLM в жизненном контуре.** Ядро детерминировано; языковые модели
   не участвуют в состоянии, выборе и действиях жизни. Причины:
   [docs/DECISION_NO_LLM_LIFE.md](docs/DECISION_NO_LLM_LIFE.md).
2. **UI read-only.** Интерфейс наблюдает и не пишет в состояние Core;
   UI — не второй источник истины.
3. **Effector действует только после policy/approval.** Прямых вызовов
   исполнителя в обход контура безопасности быть не должно.
4. **data_bootstrap ≠ data.** Загрузочные и тестовые данные не попадают
   в реальные каталоги жизни.
5. **Интерфейс не рисует то, чего не было.** Никаких выдуманных связей,
   «красивых» метрик и статусов, которых нет в состоянии.
6. **Слова не пишут ценности и мотивацию за жизнь.** Ценности и опыт
   формируются жизнью, а не текстом в конфиге.

## Процесс

1. Установите dev-зависимости и хуки:

   ```bash
   pip install .[dev]
   pre-commit install
   ```

2. Сделайте ветку от `main`.
3. Вносите изменения, соблюдая стиль окружающих модулей.
4. Статические проверки (как в CI):

   ```bash
   python -m compileall -q src/ config/ tests/ main.py main_tray.py
   python -m ruff check src/ config/ tests/ main.py main_tray.py
   python -m ruff format --check src/ config/ tests/ main.py main_tray.py
   python -m mypy --config-file pyproject.toml --explicit-package-bases --no-site-packages --follow-imports=skip main.py main_tray.py
   python -m bandit -r src/ config/ main.py main_tray.py -ll --skip B101,B601
   ```

   Те же проверки доступны через `pre-commit run --all-files`. Mypy пока
   проверяет только публичные entry points `main.py` и `main_tray.py`, а не весь
   репозиторий. Закреплённые версии и границы проверок описаны в
   [docs/static_toolchain.md](docs/static_toolchain.md).

5. Тесты:

   ```bash
   python -m pytest -q tests/test_acceptance_life_cycle.py   # приёмочный
   python -m pytest -q                                       # полный набор, ~6 минут
   ```

   Точечный запуск — `python -m pytest -q tests/<файл>` или
   `python -m pytest -k <имя>`. Для локального аналога coverage-gate:

   ```bash
   python -m pytest -q --cov=src --cov=config --cov-branch --cov-fail-under=40
   ```

   Полный замер при включении ветвлений дал 77,97 % совокупного покрытия.
   Порог 40 % пока намеренно консервативный; повышение выполняется отдельно.

Минимальный критерий готовности: статические проверки + точечный pytest
по затронутым областям. Полный прогон обязателен при изменениях жизненного
контура, перед релизом и перед синхронизацией документации.

Основная платформа — Windows 10+; Python 3.10+ (CI проверяет 3.10–3.12).

## Баги и предложения

Открывайте
[GitHub Issues](https://github.com/han13ter2014-web/Digital_being/issues)
и указывайте:

- что ожидали и что получили фактически;
- версию (пакет или коммит);
- шаги воспроизведения; для багов интерфейса — скриншот.

## Pull request

- описание: что меняет и почему;
- какие команды проверки запускали и их результат;
- правки не нарушают архитектурные границы выше;
- новые зависимости — только при необходимости: жизненному контуру
  достаточно стандартной библиотеки и NumPy, интерфейсу достаточно Tkinter.

Контекст разработки и историю архитектурных решений см. в
[docs/DEVELOPMENT_HISTORY.md](docs/DEVELOPMENT_HISTORY.md).
