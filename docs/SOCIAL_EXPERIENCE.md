# Этап 4: социальный опыт не возникает из ожидания

Удалено начисление полезного контакта за непустую pending_questions в
основном evolve middleware и legacy evolve. Исходящий вопрос и ожидание
человека больше не увеличивают trust/intimacy/familiarity.

Контакт регистрируется в ThinkingPipeline после submit_answer со статусом
answered. Повтор без ожидающего вопроса не создаёт контакт. Если submit
отказал (not_found/уже отвечен), не создаётся ни контакт, ни новое знание.

Это узкая семантика: принятие ответа считается полезным участием в диалоге
по прежней модели AttachmentSystem. Истинность/качество ответа независимо
не доказаны. Не реализованы нейтральные контакты, несогласие как полезный
разговор и отдельная оценка достоверности собеседника. Нельзя использовать
рост социального доверия как доказательство истинности утверждения.
Контакты из прочих входящих сообщений пока не регистрируются этим путём.

Тесты test_social_experience.py: 20 обновлений с pending дают ноль новых
контактов; один принятый ответ и последующие evolve дают один контакт;
отказ submit не меняет знания/отношения. Профильный набор social/personal/
knowledge: 43 passed. Прямые вызовы через Mock контролируют принятие;
интеграция настоящего вопроса/ответа проверена дополнительно ниже.

## Сквозной контроль

`test_social_life_roundtrip.py`, JSON/SQLite: настоящий ask_user создаёт
вопрос, 20 обновлений ожидания не создают отношения, настоящий submit_answer
через ThinkingPipeline добавляет один контакт и testimony с происхождением.
Повтор ответа не добавляет контакт. После save_state/create_agent personal_state
совпадает, история содержит одно взаимодействие. Контакт вводится через API,
а не через GUI/EventBus; качество и истинность ответа тест не доказывает.
Вопросы UserInteraction сами пока не входят в checkpoint; проверка повтора
после запуска не является доказательством durable exactly-once для ответов
на несколько вопросов с повторно использованными id.
