## Участок «Собеседник», ступень 1 (2026-11-01)

Закрыт по плану из 4 этапов; приёмка на живом стенде — 4/4 критерия.
Без LLM в контуре, UI read-only, слова пользователя не пишут в ценности
и мотивацию — только факты о пользователе.

   `test_user_message_routing.py`.
2. **Модель собеседника.** `src/core/user_model.py` (обещания, черты,
   последний контакт; сериализация в чекпоинт), `submit_answer(cycle=…)`
   в `user_interaction.py`, care-сообщение с обещанием в
   `proactive_communication.py`. Тесты: `test_user_model.py`.
3. **Свидетельство как знание.** `DigitalBeing.record_user_answer`: опыт
   концепта kind=testimony, source=user, сила 0.4; штамп
   `_user_explained_topics` с кулдауном `USER_EXPLAINED_COOLDOWN_CYCLES=200`
   (`config/simulation_config.py`); тема вопроса — `_topic_from_question`;
   колбэк `on_user_answer` в `OpenQuestionsManager`. Guard «не
   переспрашивать объяснённое» стоит в самом `_act_ask_user`: продолжение
   намерений передаёт target напрямую, минуя селекторы тем — живой прогон
   это показал. Подтверждение цитирует записанное
   (`_format_user_answer_result`: «Записал про «X»: «…» — буду проверять
   на своём опыте»). Тесты: `test_answer_becomes_knowledge.py`.
4. **Память диалога.** `_shared_topics` + дедуп повторов в

## Багфикс-партия 2026-11-01 (коммит 3151ce3, опубликован в origin/main)

Аудит нашёл четыре бага, бьющих по темпу воли, каналу идентификации и
непрерывности. Исправлено без изменения субъектности Core (UI остался
read-only, LLM в контур не добавлялся):

1. **Неблокирующий тик жизни.** Цикл агента выполняется в worker-потоке
   (`asyncio.to_thread` в `AgentRunner._tick_once`): синхронный Wikipedia-поиск
   (timeout 5 c × 2 языка + rate-limit) больше не замораживает EventBus,
   StatusLoop и не откладывает `tick_will`/`tick_communication`.
   Тест: `tests/test_tick_nonblocking.py`.
2. **Роутинг «просто имени».** В фазе NamingDialogue простой текст из чата
   идёт в USER_COMMAND `propose_name` (раньше — в USER_MESSAGE, подсказка
   агента вводила в заблуждение). Решение по имени по-прежнему принимает Core.
   Тест: `tests/test_chat_naming_route.py`.
3. **Потокобезопасный `ChatWindow.stop()`.** Уничтожение окна только через
   очередь (`request_close`), без `after()` из потока жизни.
4. **Гард сохранения на выходе.** `main.graceful_exit_save()` никогда не
   сохраняет из живого потока жизни: мягкая остановка → ожидание → повторное
   сохранение только если поток завершился и сам не смог. Плюс процессный
   lock на `CheckpointSerializer.save`.
   Тест: `tests/test_graceful_exit_save.py`.
5. Мелочи: честный докстринг EventBus (очередь FIFO, priority не учитывается),
   обновлён устаревший комментарий в `main.py` про события до `start()`,
   публичный `WebSearcher.cache_size()` вместо приватного `ws._cache` в `/web`.

## Неизменяемые архитектурные границы

```text

             намерения, выбор, история и память.
Delamain   = исполнительный слой и техническая память действий.
Effector   = безопасное выполнение через контракт, sandbox и approval.

Ollama /   = исторический legacy-эксперимент, не часть жизненного контура.
```

Нельзя ради демонстрации:

- выдавать желание модели за желание Core;
- подключать LLM к жизненному контуру или позволять ей выбирать цель вместо Core;
- рисовать связь, которой нет в данных;
- показывать гипотезу как знание;
- считать `queued` или `waiting_approval` выполнением;
- превращать настроение в мотивацию или ценность;
- создавать ленивые поля Core чтением UI;
- добавлять собственное хранилище истории в UI;
- запускать действие напрямую из UI в обход Effector;
- использовать внешний профиль или сеть в тесте, если можно обойтись временной
  изоляцией.

## Приёмочный сценарий

Основной тест: `tests/test_acceptance_life_cycle.py`.

Он изолирован через временные workspace и SQLite и проверяет:

```text
begin_intention()
→ EffectorRequest
→ queued
→ waiting_approval
→ approve
→ agent.tick_subsystems()
→ succeeded и реальный файл
→ finish_intention()
→ _record_core_life_episode()
→ build_life_snapshot()
→ build_life_graph()
```

Terminal Effector result теперь автоматически замыкает когнитивное
intention только при явном `detail.metadata.intention_id`. Core завершает
только запись со статусом `started`, записывает один life episode и защищает
повторный terminal result. Результат без `intention_id`, а также `queued` и
`waiting_approval`, историю не меняют.

## Проверенные практические особенности окружения

- Windows PowerShell: не использовать `&&` и shell heredoc `python - <<'PY'`;
- тесты не имеют права трогать реальные пути данных: только
  `data_path()`/корень изоляции из conftest; относительный
  `'data/checkpoints'` в cleanup-херпере теста однажды удалил все живые
  профили (гибель первой Тэсс);
- кириллица в stdout PowerShell может отображаться повреждённо — для проверки
  читать файлы или писать вывод в UTF-8;
- `deepcopy(agent.__dict__)` падает из-за `RLock`; сравнивать конкретные поля;
- `_intention_history`, `_waiting_intentions`, `_method_preferences` создаются
  лениво — читать через безопасный `_own()`;
- для теста отсутствующего Effector явно делать
  `agent.delamain_effector = None`;
- Tk-скриншот на Windows требует `root.attributes("-topmost", True)`;
- полный набор без benchmarks занимает около 5 минут — не запускать его
  после каждого пробного редактирования, сначала использовать профильный набор.

## Правило обновления этого документа

После завершения значимого участка AI должен обновить здесь:

- дату;
- текущий статус;
- последний коммит;
- тестовый результат;
- новые архитектурные ограничения;
- следующий ограниченный шаг.

После этого обновление должно быть закоммичено вместе с работой или отдельным
документальным коммитом. Не оставлять handoff-документ заведомо устаревшим.
