### Ступень 2 — «понимание речи и гигиена тем» (3 этапа)

1. **Вопросы пользователя к сущности.** В `dialogue_acts.py` новый акт
   ACT_ASK_ABOUT_SELF: маркеры «как тебя зовут», «кто ты», «чем
   занимаешься», «что ты знаешь» (настоящие вопросы перенести из
   social-таблицы, где они дают «Я слышу тебя» вместо ответа).
   Маршрутизатор отвечает честными формулами из read-only состояния
   Core: имя, циклы, число концепций, текущее занятие, что помнит о
   пользователе (обещания, последние темы). Тесты: классификация +
   содержание ответов.
2. **Знание, предложенное без вопроса.** Явная формула «X — это Y» в
   речи пользователя становится свидетельством через
   `record_user_answer(X, …)` с детерминированным извлечением темы —
   вместо «Не нашел файл для 'вся фраза целиком'» и мусорных концептов.
   Тесты: паттерн, отрицания, граница неузнанного.
3. **Гигиена тем.** Мета-слова собственных шаблонов сущности («вопрос»,
   «тема», «ответ») не выбираются целями исследования/вопросов.
   Социальные акты и дословные реплики пользователя не попадают в
   «последние темы диалога» care-сообщений — живой прогон показал
   цитату протеста в «Помню… мы говорили». Протест «ты повторяешься»
   дополнительно ставит штамп текущей теме. Тесты.

Приёмка ступени 2: живой зонд нового сценария (вопрос к сущности,
«X — это Y», гигиена тем) + hands-off наблюдение без дублей и
переспросов; полный pytest.

## Реализованные UI-модули

- `src/ui/theme.py` — палитра, формы узлов, шрифты, spacing;
- `src/ui/life_snapshot.py` — read-only DTO Core;
- `src/ui/life_view.py` — форматтеры экрана «Сейчас»;
- `src/ui/graph_view.py` — честный сборщик и детерминированная раскладка
  карты жизни;
- `src/ui/diary_view.py` — форматтеры дневника и занятий;
- `src/ui/main_window.py` — Tk-оболочка и страницы.

Карта жизни показывает только:

- концепции из `mental_models.concepts`;
- намерения из истории/ожиданий;
- занятия, реально связанные с намерением;
- ценности `innate_values` без выдуманных рёбер к концепциям;
- реальные связи mental model, intention → topic,
  intention → activity.

Лимиты карты: 200 узлов, 500 связей, 120 концепций, 40 намерений,
8 ценностей.

## Приёмочный сценарий

Основной тест: `tests/test_acceptance_life_cycle.py`.

Он изолирован через временные workspace и SQLite и проверяет:

```text
begin_intention()
→ EffectorRequest
→ queued
→ waiting_approval
→ approve
→ agent.tick_subsystems()
→ succeeded и реальный файл
→ finish_intention()
→ _record_core_life_episode()
→ build_life_snapshot()
→ build_life_graph()
```

Terminal Effector result теперь автоматически замыкает когнитивное
intention только при явном `detail.metadata.intention_id`. Core завершает
только запись со статусом `started`, записывает один life episode и защищает
повторный terminal result. Результат без `intention_id`, а также `queued` и
`waiting_approval`, историю не меняют.

## Что делать дальше

v1 и этап 7 закрыты. Следующий разумный шаг — не новый экран и не миграция
стека, а приёмка и наблюдение:

2. проверить restart continuity для intention, diary и Effector approval;
3. провести ручную 60–90-секундную демонстрацию:

участка с критерием приёмки.

## Проверенные практические особенности окружения

- Windows PowerShell: не использовать `&&` и shell heredoc `python - <<'PY'`;
- тесты не имеют права трогать реальные пути данных: только
  `data_path()`/корень изоляции из conftest; относительный
  `'data/checkpoints'` в cleanup-херпере теста однажды удалил все живые
  профили (гибель первой Тэсс);
- кириллица в stdout PowerShell может отображаться повреждённо — для проверки
  читать файлы или писать вывод в UTF-8;
- `deepcopy(agent.__dict__)` падает из-за `RLock`; сравнивать конкретные поля;
- `_intention_history`, `_waiting_intentions`, `_method_preferences` создаются
  лениво — читать через безопасный `_own()`;
- для теста отсутствующего Effector явно делать
  `agent.delamain_effector = None`;
- Tk-скриншот на Windows требует `root.attributes("-topmost", True)`;
- ImageGrab может захватить системную панель Task View — после съёмки
  визуально проверять кадры на системные оверлеи, пересъёмка в
  resume-режиме с Esc-очисткой оверлеев;
- полный набор без benchmarks занимает около 5 минут — не запускать его
  после каждого пробного редактирования, сначала использовать профильный набор.

## Правило обновления этого документа

После завершения значимого участка AI должен обновить здесь:

- дату;
- текущий статус;
- последний коммит;
- тестовый результат;
- новые архитектурные ограничения;
- следующий ограниченный шаг.

После этого обновление должно быть закоммичено вместе с работой или отдельным
документальным коммитом. Не оставлять handoff-документ заведомо устаревшим.
