# Этап 3: непрерывность индивидуальности — первый участок

Предыдущий блок расписания зафиксирован 5932f5a (1203 passed, 2 skipped).

В обычный checkpoint добавлена опциональная секция personal_state:

- актуальный список ценностей, включая пустой;
- полный WillRegistry: события, счётчики и последний цикл изменения ценностей;
- недавние отказы, определяющие существующий лимит;
- отношения: точные числовые значения, число взаимодействий, время и история.

Сериализация отношений не использует округлённую UI-сводку. Восстановление
не вызывает record/update: перезапуск не добавляет переживаний и не меняет
доверие. Экземпляры registry/attachment/value_evolution сохраняются, чтобы
адаптеры и другие модули продолжали использовать общие ссылки. Перед любыми
мутациями checkpoint проверяются типы, диапазоны и форма personal_state.

При отсутствии секции (старый checkpoint) остаются начальные значения:
утраченную историю не восстанавливаем из догадок. Добавление секции обратно
совместимо для текущего загрузчика; версия схемы не повышена, поскольку
обязательные поля/прежний смысл не изменены.

## Проверки

`tests/test_personal_continuity.py` проходит save_state → create_agent для
JSON/SQLite. Добавляется ценность, удаляется другая, регистрируется одно
взаимодействие и серия отказов. После запуска всё совпадает, ограничения
частоты сохраняются, новый акт продолжает прежний счётчик. Пустые ценности
не подменяются дефолтами. Некорректная секция отклоняется до изменения.

Профильный прогон personal/serializer/validation/restart: 103 passed.

## Единая сохраняемая идентичность

Арбитр подключён к тому же self, который хранит SoulController. Оценка
кандидатов читает core_identity/stability, больше не вызывает synthesize
для каждого рассмотренного варианта. Изменение идентичности в обычном
soul tick пока сохранено — его основания требуют отдельной работы.

В personal_state добавлено самоописание, core_values, стабильность и
история self. Нулевое значение стабильности и пустой список core_values
сохраняются точно, не заменяются default через `or`. Восстановление меняет
существующий shared self, не создаёт нового. Регрессии test_shared_identity.py
проверяют отсутствие synthesize при выборе и нормальный старт JSON/SQLite.
Профильный набор identity/personal/validation/experiments: 73 passed.

Это не объединение всех представлений ценностей: ValueEvolution.current_values
и self.core_values пока отдельные поля с разным потреблением. Не утверждаем,
что они уже образуют одну каузальную систему предпочтений. Dialogue/ethics
арбитра также пока отдельные экземпляры, эта правка касается self.

## Сохранение обученной модели действий

Секция active_inference (version=1) сохраняет priors/posteriors скрытых
состояний, переходы действий, температуру и её параметры, ограниченные
буфер опыта (1000), историю выбора (100) и free-energy history (100).
Numpy-массивы записываются как списки, восстанавливаются в существующий
engine без разрыва ссылок planner/inference/model/agent. Новое обучение
продолжает сохранённые матрицы.

Предварительная проверка отклоняет NaN, отрицательные вероятности,
неверные суммы/размеры и несовместимые имена модели; compatibility с живым
engine проверяется до изменения памяти агента. Отсутствующая секция старого
checkpoint оставляет начальную модель. Состояние RNG, параметры неизменяемой
likelihood-модели и динамические предпочтения не сохраняются; последние
пересчитываются из агента. Поэтому идентичный следующий случайный выбор
не гарантируется.

Тесты test_inference_continuity.py: реальные learn_from_experience меняют
матрицу; JSON/SQLite startup сохраняет всё, повторное обучение меняет её
дальше; повреждённая форма отклоняется до мутации. Набор inference/personal/
identity/serializer/validation: 99 passed; дополнительные backup/attention/
runtime: 13 passed.

Обнаружена существующая матрица repair.cognitive_coherence без одноимённого
hidden state. Её не удаляем и не преобразуем ради сохранения; проверяем
против исходной структуры engine. Каузальное использование этого перехода
требует отдельного исправления, а не притворной успешной сериализации.

Общий прогон выявил ошибку валидатора: опыт действий вне model.actions
(например communicate) отвергался, хотя действующий learn_from_experience
уже пропускает такие записи. Исправлено: непустое строковое имя допустимо,
наблюдение сохраняется, но матрицы для несуществующего действия не создаются.
Регрессия проверяет 32 таких записи, точный roundtrip и отсутствие изменения
переходов при обучении. Проверка inference/maturity/personal/identity:
25 passed. Предыдущий общий прогон: 1212 passed, 1 failed, 2 skipped —
не считается подтверждением окончательной версии.

## Незавершённое исследование

В open_questions сохраняются реальные explorations (cycle/thought/strategy),
а не только их число. Обычный запуск продолжает следующую стратегию и не
обнуляет лимит попыток. Применение снимка заменяет очередь, не дописывает
её повторно. Пустой сохранённый список очищает вопросы текущего объекта.
Секция валидируется до мутаций. Старые снимки без истории её не обретают:
прежний счётчик сам по себе не позволяет восстановить содержание/стратегии.

Тесты inquiry_continuity для JSON/SQLite: попытка 1 сохранена, после запуска
следует 2/3, затем 3/3, затем прежний алгоритм завершает попытки. Семантика
`answered=True` для исчерпанного неразрешённого вопроса не исправлена этим
этапом и требует отдельного статуса в дальнейшем. Повторное применение
не дублирует вопросы. Профильный набор inquiry/serializer/validation/inference:
96 passed. Старый тест «история не сохраняется» заменён проверкой её точности.

## Сквозная проверка одного снимка

`test_personal_life_roundtrip.py` объединяет изменения ценности, одно реальное
вызванное взаимодействие, отказ, самоописание, 32 записи обучения и первую
попытку собственного вопроса. После одного save_state/create_agent проверяет
точное совпадение personal_state, Active Inference, памяти и истории вопроса.
Затем обучение продолжается с сохранённой матрицы, вопрос идёт к попытке 3/4,
а новый волевой акт продолжает прежний счётчик. Общие ссылки self/registry
сохраняются, cooldown изменения ценностей не сбрасывается. JSON/SQLite.

Это контролируемый интеграционный сценарий: события задаются через API,
а не порождаются самостоятельно в длинной жизни. Он подтверждает
непрерывность, не самостоятельное происхождение ценностей и не сознание.
Профильный прогон whole/personal/identity/inference/inquiry: 16 passed.

Итоговый общий прогон этого блока: **1219 passed, 2 skipped**, без benchmarks,

## Границы

Это сохранение, а не новый механизм желаний или эволюции ценностей.
Наличие записи об отказе ещё не означает каузальный запрет исполнения:
интеграция отказа/stop с выбором остаётся впереди. Исходное начисление
привязанности из pending_questions ещё не исправлено, поэтому сохранность
отношения не доказывает достоверность его происхождения.

Не включены пока единая идентичность soul/arbitrator, обучение Active
Inference, квест, паузы общения и история размышлений открытых вопросов.
Не заявляем сохранение всей индивидуальности завершённым. Журналы
сохраняются целиком; вопросы архива/инкрементального хранения остаются.
