# Декабрьский маршрут: мотивация, curiosity и голос/LLM

Дата: 2026-11-20.

Основание: `body_plan.md`, строки органа «Потребности/мотивация», «Следопыт
тем (curiosity)» и «Голос (генеративная речь)».

Статус: **D0–D8, D2-R, D6-R и implementation D6-4 завершены локально
2026-11-21**. Это завершённый маршрут исследования и принятия решений, а не
предварительное разрешение менять потребности, веса, curiosity, создавать
нейросетевые органы или подключать LLM.

## 1. Правила маршрута

1. Сначала наблюдаемая функция, затем критерии, затем изолированные
   наблюдения и только после этого — решение о ревизии.
2. Сравнение идёт по функциям: возврат к baseline, насыщение, фрустрация,
   конкуренция, сохранность и влияние на выбор. Сходство с человеком не
   является критерием.
3. `pressing` и `urgency` остаются разными шкалами. Legacy-шкалы не
   переносятся в основной контур без отдельного преобразования.
4. Все прогоны используют изолированный `DIGITAL_BEING_DATA_DIR` в `tmp/`.
   Живые `data/` и живая сущность не используются как тестовый стенд.
5. До decision gate не меняются production-формулы, наборы потребностей,
   драйвов, награды, действия и политика арбитра.
6. Decision gate не предполагает обязательную реализацию: результатом может
   быть «оставить как есть».
7. Голос/LLM — только архитектурное решение о природе сущности. В этом
   маршруте нет скрытого этапа подключения модели.
8. Commit/push и включение новых поведенческих режимов — только по отдельному
   явному разрешению владельца на конкретный набор изменений.

## 3. Порядок и зависимости

```text
D0 → D1 → D2 → D3 → D2-R → D4 → D5 → D6 → D6-R → D6-4 → D7 → D8
```

Работа идёт последовательно, чтобы выводы и критерии предыдущего этапа не
терялись между направлениями. Если наблюдение показывает недостаток данных,
этап не «проходит условно»: фиксируется ограничение и следующий шаг по
получению именно этих данных.

## 4. Что может появиться после decision gate

Только после D3, D6 или D7 владелец может одобрить отдельный
implementation-тикет.
Такой тикет обязан содержать:

- подтверждённую функциональную проблему и источник наблюдения;
- инварианты, которые нельзя менять;
- минимальный production-diff;
- regression и differential-сценарии до/после;
- restart и изоляцию жизни;
- полный regression и статические гейты для изменения кода;
- отдельное решение о commit/push.

Этот маршрут сам по себе не создаёт таких тикетов. По решениям D3 сначала
выполняется D2-R: implementation возможен только после его новых результатов
и отдельного решения владельца.
