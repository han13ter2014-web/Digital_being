# Приёмочная демонстрация v1

## Что демонстрирует

Один изолированный жизненный цикл без сети, Ollama и GUI:

```text
Core выбирает намерение
  → Delamain принимает безопасный план
  → Effector ждёт подтверждения
  → пользовательское подтверждение
  → Core-owned clock выполняет действие
  → результат возвращается в Core
  → намерение завершается
  → Core записывает life episode
  → дневник показывает событие
  → карта показывает намерение и реальные связи
```

Сценарий находится в `tests/test_acceptance_life_cycle.py`.
Он использует временную рабочую область и временную SQLite-базу; рабочий
профиль проекта не затрагивается.

## Как проверять

Из корня проекта:

```powershell
python -m pytest -q tests/test_acceptance_life_cycle.py
```

Ожидаемый результат:

```text
1 passed
```

## Что именно проверяется

1. Core создаёт намерение `create_draft` с реальной причиной и темой.
2. Delamain принимает `EffectorRequest`, но не выполняет его сразу.
3. До подтверждения состояние остаётся `waiting_approval`.
4. После подтверждения действие всё ещё выполняется только через Core-owned
   `EffectorDriver`.
5. Создаётся реальный файл в изолированной creative workspace.
6. Успешный terminal result возвращается в Core.
7. Core обновляет опыт способа `create_draft`.
8. Завершённое намерение записывается как autobiographical life episode.
9. Read-only snapshot видит эпизод в дневнике.
10. Карта жизни видит:
    - узел намерения;
    - узел занятия;
    - узел концепции «память»;
    - связь «намерение → занятие»;
    - связь «намерение → тема».

## Важное ограничение v1

Сейчас terminal result Effector не завершает intention автоматически: Core
намеренно не угадывает, какой когнитивный эпизод означает технический
результат. В демонстрации переход сделан явным Core-owned мостом:
`finish_intention()` → `_record_core_life_episode()`.

Это честнее, чем автоматически записывать любой успешный файл как внутреннее
переживание. Автоматизация этого перехода — отдельное архитектурное решение,
а не косметическая задача UI.

## Что увидит внешний зритель

В текущем интерфейсе после такого цикла реальные изменения доступны сразу в
трёх местах:

- **Сейчас** — выбранное занятие и причина;
- **Дневник** — завершённый жизненный эпизод;
- **Карта жизни** — намерение, тема и занятие с записанными связями.

Это и есть минимальная демонстрация отличия Digital Being от обычного чата:
действие не заканчивается ответом модели, а проходит через состояние, policy,
подтверждение, Core и память.
