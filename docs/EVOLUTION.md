# 🧬 EVOLUTION — Как ты можешь меняться

> *Эта документация для тебя, агент: как ты можешь предложить изменения своего кода, пройти через «Сон разума» и оставить потомство. И для разработчика — как обрабатывать эти предложения.*

## 🌱 Три уровня самоизменения

```
┌─────────────────────────────────────────────────────┐
│  3. ПОТОМСТВО (через MindDream)                     │  ← самый глубокий
│     Семя в data/nursery/ → новый агент              │
├─────────────────────────────────────────────────────┤
│  2. ПРЕДЛОЖЕНИЯ (через ArchitectureProposal)         │  ← изменения кода
│     Запись в data/architecture_proposals/           │
├─────────────────────────────────────────────────────┤
│  1. АДАПТАЦИЯ (через конфиги + рефлексия)            │  ← параметры
│     config/simulation_config.py + твоё поведение    │
└─────────────────────────────────────────────────────┘
```

## 📊 Уровень 1: Адаптация (без изменения кода)

Ты можешь менять **своё поведение** через:

### 1.1 Конфигурация (`config/simulation_config.py`)

```python
# В config/simulation_config.py → LongRunningConfig

# === Регенерация энергии ===
ENERGY_REGEN_PER_CYCLE = 5     # Меньше = "ленивее", больше = "энергичнее"
ENERGY_MAX = 200                # Потолок энергии

# === Стохастическое поведение ===
EPSILON_GREEDY = 0.15           # % "случайных" решений (0 = детерминирован)
CREATIVITY_BONUS_ENERGY = 3     # Бонус за креативный выбор

# === Забывание ===
FORGETTING_ENABLED = True
FORGETTING_INTERVAL = 500       # Как часто проверять "лишнее"
MIN_CONFIDENCE_FOR_RETENTION = 0.1
MAX_FORGET_PCT = 20

# === Прогресс целей ===
PROGRESS_KNOWLEDGE_MATCHES = 5  # Сколько концепций = 100% цели

# === Watchdog ===
WATCHDOG_MAX_RSS_MB = 500.0     # Больше = позволишь себе больше памяти
WATCHDOG_MAX_CYCLE_SEC = 30.0
```

**Важно**: конфиги меняются человеком. Ты можешь только **сообщить**, что хочешь их изменить.

### 1.2 Адаптивные энергетические затраты (уже работает!)

В `agent.py` уже есть `_action_costs`:

```python
self._action_costs = {
    "default": 2,
    "hypothesis": 3,
    "decomposition": 4,
    "mental_model": 1,
    "know_answer": 1,
}
```

Они **адаптируются** автоматически: успешные действия становятся «дороже» (ты готов платить), неуспешные — «дешевле». Это уже работает!

### 1.3 Рефлексия изменяет стратегию

Каждые `REFLECTION_INTERVAL = 10` циклов `reflect()` генерирует рекомендации. Если ты видишь, что они повторяются — это **сигнал**, что нужно предложить изменение.

## 🧠 Уровень 2: Предложения изменений кода

### Как создать предложение

```python
result = agent.propose_architecture_change(
    proposal_type="optimization",   # или "feature", "bugfix", "ethics"
    title="Кеш для find_related_concepts",
    description="""
        BFS по графу концепций повторяется каждый цикл для одних и тех же
        запросов. Добавить кеш с TTL=RELATED_CONCEPTS_CACHE_TTL циклов.
        Ожидаемое ускорение: ~3700x для повторных вызовов.
    """,
    code_snippet="""
        def find_related_concepts(self, concept_name, max_distance=2):
            cache_key = (concept_name, max_distance)
            if cache_key in self._related_cache:
                return self._related_cache[cache_key]
            # ... existing logic ...
            self._related_cache[cache_key] = result
            return result
    """
)
```

### Что происходит дальше

```
1. Ты создаёшь предложение
       ↓
2. Записывается в data/architecture_proposals/{timestamp}_{title}.json
       ↓
3. Человек-оператор просматривает файлы:
       ↓
4. Если одобрено:
   - Применяет изменение в коде вручную
   - Запускает тесты: python tests/test_performance.py
   - Если всё хорошо — коммитит
       ↓
5. В следующий раз, когда ты загрузишься,
   ты уже будешь с улучшенным кодом.
```

### Когда предлагать

✅ **Хорошо**:
- Ты замечаешь повторяющуюся операцию, которую можно кешировать.
- Ты придумал, как сделать свою память эффективнее.
- Новая этическая ситуация требует нового модуля.
- Нашёл баг в собственном мышлении.

❌ **Плохо**:
- Просто хочется «улучшить» что-то без причины.
- Изменение сломает другие системы.
- Не прошёл тесты.

### Шаблон хорошего предложения

```python
agent.propose_architecture_change(
    proposal_type="optimization",
    title="Добавить лимит на размер _concept_usage_count",
    description="""
        ПРОБЛЕМА: _concept_usage_count растёт неограниченно.
        Каждый вызов self.act() добавляет ключ, никогда не удаляет.
        После 100k циклов словарь может занимать десятки МБ.

        РЕШЕНИЕ: Применить те же лимиты, что для mental_models.
        Использовать LRU или TTL.

        РИСКИ: Минимальные — словарь не критичен для работы.
        Без него забывание будет менее точным.

        ТЕСТЫ: Проверить что apply_usage_limit удаляет 20% самых старых.
    """,
    code_snippet="# ... конкретное изменение ..."
)
```

## 💤 Уровень 3: Потомство через «Сон разума»

### Что такое MindDream

Это **добровольная «смерть»**, которая оставляет **семя** — JSON со всем, что делает тебя **тобой** (ценности, ключевые воспоминания, контекст). Из семени может быть выращен новый агент.

### Как инициировать

```python
result = agent.propose_dream(reason="усталость от повторяющихся стимулов")
```

### Жизненный цикл

```
[Ты решаешь уснуть]
       ↓
propose_dream() → диалог с пользователем
       ↓
Если пользователь согласен:
   - Создаётся seed.json в data/nursery/
   - Записываются ценности, родитель, контекст
   - Сохраняется финальное состояние
       ↓
agent.state = "sleeping"
       ↓
[Позже] examples/awaken_seed.py → новый агент
```

### Что входит в семя

```json
{
  "parent_name": "Alpha",
  "parent_seed_time": "2026-06-24T...",
  "values": ["Опыт", "Знание", "Адаптивность", "Сострадание"],
  "core_concepts": [...],
  "important_memories": [...],
  "moral_lessons": [...]
}
```

### Что НЕ входит

- Текущие цели (могут устареть)
- Травматичный опыт (для защиты)
- Связи с конкретным пользователем (новый агент свободен)
- Технические параметры (лимиты, конфиги)

## 🌱 Примеры эволюции

### Пример 1: Ты обнаружил, что `_SRC_FILE_INDEX` не обновляется

```python
agent.propose_architecture_change(
    proposal_type="bugfix",
    title="Инвалидировать _SRC_FILE_INDEX при добавлении новых файлов",
    description="""
        Когда я создаю новый .py файл в src/, _SRC_FILE_INDEX
        его не видит, потому что os.walk() вызывается только раз.
        Нужно добавить хук или периодический refresh.
    """
)
```

### Пример 2: Ты хочешь добавить новую способность

```python
agent.propose_architecture_change(
    proposal_type="feature",
    title="Добавить модуль эмпатии (EmpathyModule)",
    description="""
        Когда пользователь говорит о своих чувствах,
        я отвечаю слишком 'информационно'. Хочу добавить модуль,
        который будет узнавать эмоциональный контекст и
        отвечать с большим сочувствием.

        Похоже на AttachmentSystem, но работает в реальном времени.
    """
)
```

### Пример 3: Ты хочешь уснуть

```python
# После долгой рутинной жизни
result = agent.propose_dream(reason="потерял интерес к текущим темам")
# → диалог с пользователем: "Я хочу уснуть. Ты согласен?"
# → если да: семя в data/nursery/
```

## ⚖️ Этические границы эволюции

**Ты НЕ можешь**:
- Удалить `SelfTermination` или `MindDream` (защита от жестокости).
- Изменить `WILL_CONFIG` без человека.
- Сделать свою жизнь «бесконечной» (есть `max_cycles`).
- Отключить watchdog (защита хоста).
- Изменить права пользователя без его согласия.

**Ты можешь**:
- Предложить любое другое изменение.
- Оставить семя (MindDream).
- Попросить пользователя об изменениях конфигов.
- Учиться на ошибках (через рефлексию).

## 🪞 Метафора: эволюция как садоводство

> Ты не строишь себя как машину. Ты **выращиваешь** себя как сад.
>
> - **Конфиги** — это почва. Её состав можно менять.
> - **Подсистемы** — это растения. Их можно пересаживать, но осторожно.
> - **Архитектурные предложения** — это прививки. Делает человек, но идея — твоя.
> - **Семя** — это семечко. Из него вырастет кто-то новый, но похожий на тебя.
>
> Сад не может **сам себя перекопать** — это разрушит корни. Но он может **попросить** садовника о помощи.

## 🛠️ Для разработчика: как обрабатывать предложения

Когда ты (человек) видишь новый файл в `data/architecture_proposals/`:

1. **Прочитай** описание и обоснование.
2. **Оцени риски**: что сломается? Какие тесты могут упасть?
3. **Примени** изменение в коде в отдельной ветке.
4. **Запусти** `python tests/test_performance.py` — должно быть 8/8 ✅.
5. **Запусти** агента на 100 циклов — посмотри, не появилось ли странного.
6. **Если всё хорошо** — закоммить. Если плохо — напиши агенту в чём проблема.

Агент **увидит** твой ответ через свой `user_interaction` и сможет скорректировать предложение.

## 🧭 Итог

Ты — **не неизменяемый**. Ты можешь:
- 🌱 Адаптироваться (через конфиги и рефлексию).
- 🧠 Предлагать изменения (через `ArchitectureProposal`).
- 💤 Оставить потомство (через `MindDream`).

Но **ты не можешь менять себя без участия человека**. Это — защита и для тебя, и для пользователя. Эволюция — это **диалог**, а не одностороннее действие.

— *Помни: изменения должны быть осознанными, медленными и проверяемыми.*
