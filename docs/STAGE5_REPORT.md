# Этап 5 — отчёт: смысл и метрики

Цель этапа: сделать так, чтобы действия агента имели измеримые последствия,
а метрики не врали. Без новых подсистем и без переписывания `agent.py`.

Главный вопрос этапа: **можно ли по состоянию агента доказать, что он
продвигается, а не просто пишет в лог одно и то же?**

## 1. Что было не так

По baseline (реальный лог за 125 дней, см. `docs/BASELINE.md`):

| Проблема | Факт |
|---|---|
| Одно действие доминирует | 84,2 % действий — декомпозиция |
| Цели не завершаются | `completed_goals = 0` за 186 циклов |
| Прогресс цели — фиксированная доля | одно совпадение давало `100 / matches_needed` и не накапливалось |
| Счётчик целей дробный | `GoalSubsystem.check_progress` делал `completed_goals += 0.5` |
| Два счётчика целей | `agent.completed_goals` и `goal_subsystem.completed_goals` жили отдельно |
| `cycle_count` в CLI не обновлялся | чекпоинты, эволюция и мотивация видели цикл 0 |
| Тип действия не измерялся | в логе было `Выполняет: Ответ: ...`, все действия выглядели одинаково |
| Декомпозиция ничего не порождала | под-вопросы выводились в текст и исчезали |
| Служебная аннотация попадала в анализ | `[стратегия=mental_model_lookup, попытка 1/5]` разбиралась как тема |
| Цели без правила не могли завершиться | у врождённых целей не было ни одного правила |

## 2. Что изменено

### 2.1. Прогресс целей

`DigitalBeing._check_goal_progress` переписан:

* прогресс накапливается по **уникальным темам**: `pct = совпадения / matches_needed`;
* при 100 % цель завершается **ровно один раз**, начисляется бонус энергии;
* энергия клампится `ENERGY_MAX`;
* короткие ключевые слова (`я`, `мой`) матчатся только как отдельные токены,
  иначе «я» находилось внутри «функция»;
* для целей без специализированного правила работает `general_learning`
  (уникальные темы, 5 совпадений). Это явная операционализация: иначе
  «Понять, кто я» не завершится никогда;
* для Python и фактов добавлен `requires_answer`: встреча с вопросом ещё не
  значит «выучил» или «собрал факт». Эти цели растут только когда ответ
  реально найден (KB, файл, web, ментальная модель);
* темы самопонимания расширены до доступных в пуле (сознание, мышление,
  эмоции, свобода, существование, смысл жизни и т.д.).

`GoalSubsystem`:

* `complete_goal` идемпотентен;
* `check_progress` больше не прибавляет `0.5` к счётчику;
* счётчик всегда целый.

Синхронизация:

* `agent.complete_goal` делегирует подсистеме и забирает оттуда счётчик и
  активную цель;
* `set_goal`, `_set_next_goal` и восстановление чекпоинта синхронизируют
  `goals`, `active_goal`, `completed_goals` и `_goal_progress` с подсистемой.

### 2.2. Чекпоинты

`checkpoint_serializer` теперь сохраняет `percentage` и
`last_update_cycle`, а не только список совпавших тем. Старый формат
(`goal_id: [темы]`) по-прежнему читается. После restore подсистема целей
синхронизируется с агентом.

### 2.3. Циклы и энергия

`main.py` после `cycle_count += 1` обновляет `agent.cycle_count`. Раньше
росла только локальная переменная, поэтому чекпоинты сохраняли цикл 0, а
`save_state` срабатывал каждый цикл. Критическое восстановление энергии
теперь клампится `ENERGY_MAX`, а не жёсткими 100.

### 2.4. Типы действий

Добавлен `_action_type_counts` и строка лога:

```
Выполняет [hypothesis]: Ответ: ...
Выполняет [search_miss]: Ответ: Не нашел файл для ...
```

Классификация: `hypothesis`, `decomposition`, `know_answer`, `search_miss`,
`user_answer`, `repair`, `deep_rest`, `checkpoint_now`, `default`.
`get_full_state()["agent"]["action_types"]` отдаёт распределение. Это
позволяет измерять смысл действий, а не только их количество.

### 2.5. Декомпозиция

* Служебная аннотация `[стратегия=...]` вырезается до анализа. Раньше она
  попадала в под-вопросы и порождала мусорные концепции.
* Один и тот же запрос разбирается **один раз за сессию**
  (`_decomposed_queries`). Это прямое лекарство от baseline-повтора
  «что такое такое» 252 938 раз.
* Декомпозиция ставит в очередь **один** ещё не встречавшийся под-вопрос
  с одной попыткой. Раньше 3 вопроса × 5 попыток вытесняли тематический пул.
* Generic-декомпозиция срабатывает только на явной связке («X и Y», «X vs Y»).
  «Компьютерное зрение» больше не превращается в «что такое компьютерное».
* `tools/stage1_smoke.py` теперь обновляет `agent.cycle_count` и записывает
  попытки исследования открытых вопросов, как это делает CLI.

### 2.6. Внутренняя мотивация

`_set_intrinsic_goal` больше не подменяет `active_goal` словарём без `id`.
Цель создаётся через `set_goal(..., activate=True)`, попадает в `goals`,
получает id, а её прогресс пишется в `_goal_progress`, а не в `None`.
Предыдущая активная цель возвращается в `pending` и не теряется.

### 3.2. Изолированный smoke, 300 циклов, web отключён

До финальных правок декомпозиции:

| Метрика | Значение |
|---|---|
| Действий | 298 |
| Уникальных действий | 51 |
| Максимальный повтор | 25 |
| `search_miss` / `decomposition` | 239 / 59 |

После:

| Метрика | Значение |
|---|---|
| Действий | 299 |
| Уникальных действий | 57 |
| Максимальный повтор | 14 |
| `search_miss` / `decomposition` | 294 / 5 (1,7 %) |
| Завершённых целей | 4 |
| Прогресс целей 1–4 | 100 % |
| Новых концепций | 51 |
| `bad_decomposition` | 0 |
| Энергия min / final | 113 / 200 |

4 завершённые цели — это врождённые цели 1–4. Активной стала
«Выучить основы Python»; она не растёт, потому что web в smoke отключён и
ответов по Python нет. Это ожидаемое поведение `requires_answer`.

### 3.3. Честная оговорка

В offline-smoke 98 % действий — `search_miss`. Это не «успех», а
диагностика: без сети и файлов агент в основном ищет и не находит. Этап 5 не
прячет это, а делает видимым. С включённым web распределение будет другим,
но проверять его нужно отдельным прогоном с сетью.

Врождённые цели 2–4 («понять других», «модель мира», «когнитивные
способности») используют `general_learning`: уникальные темы, 5 совпадений.
Это не доказательство социального понимания, а явно выбранная метрика
«агент осваивает новое». Для Python и фактов метрика строже — нужен ответ.

## 4. Тесты

Добавлен `tests/test_stage5_meaning.py` — 13 тестов:

* накопление прогресса и завершение ровно один раз;
* `requires_answer` для Python;
* кламп бонусной энергии;
* короткое «я» не матчится внутри «функция»;
* `general_learning` для цели без правила;
* целый счётчик и идемпотентность `GoalSubsystem`;
* сохранение процента в чекпоинте и старый формат;
* синхронизация подсистемы после restore;
* `main.py` обновляет `agent.cycle_count`;
* счётчик типов действий и `get_full_state`;
* внутренняя мотивация создаёт цель с id;
* декомпозиция ставит один под-вопрос и не повторяет запрос;
* аннотация стратегии не попадает в анализ;
* словосочетания не дробятся на отдельные слова.

`compileall` — OK. `hygiene_scan`: 0 unused-import, 0 bare-except,

## 5. Как воспроизвести

```bash
python tools/stage1_smoke.py --cycles 300
python -m pytest tests/test_stage5_meaning.py -q
```

Smoke пишет `action_types`, `completed_goals`, `active_goal` и
`goal_progress` в JSON. Именно эти поля, а не объём лога, показывают,
работает ли этап.

## 6. Что осталось за этапом 6
