# Этап 2 — отчёт

Цель этапа: не пускать мусор в базу знаний и в граф концептов.
Источник мусора — Wikipedia-фоллбэк: на запросы вроде «?», «s 1» или
«что такое меня» он отдаёт страницы-неоднозначности и случайные статьи.

## 1. Что сделано

### 1.1. Общий фильтр качества

Новый модуль `src/memory/knowledge_quality.py` — единственный источник правил
для рантайма и для ручной чистки.

Ключ записи отбрасывается, если он:

* пустой;
* служебное слово (`что`, `такое`, `меня`, `ты`, `это`, …);
* не содержит букв (`?`, `42`);
* короче 2 символов;
* заглушка (`s_1`, `s_45`, `test`, `tmp`, `none`).

Определение отбрасывается, если оно:

* пустое или короче 15 символов;
* содержит маркеры страницы-неоднозначности (`may refer to`,
  `может означать`, `может относиться к`).

Для поиска добавлены две проверки:

* `is_worth_searching(query)` — не идти в сеть с мусорным запросом;
* `is_relevant(query, title, extract)` — в статье должно встретиться
  хотя бы одно содержательное слово запроса.

### 1.2. Где включён фильтр

| Место | Что делает |
|---|---|
| `DigitalBeing._load_knowledge_base` | отбрасывает мусор при загрузке и пишет, сколько отбросил |
| `DigitalBeing._prune_knowledge_base` | лечит базу перед каждым сохранением (даже если мусор пришёл из старого чекпоинта) |
| `KnowledgeSubsystem.load/save/prune_if_needed` | то же для прямых вызовов подсистемы |
| `KnowledgeSubsystem.add_definition` | не принимает мусор, возвращает `added=False` и `reason` |
| `WebSearcher.search` | нормализует запрос («что такое счастье» → «счастье»), отсекает мусор до сети |
| `WebSearcher._fetch` | отклоняет страницы-неоднозначности и нерелевантные статьи; при низком качестве RU пробует EN |
| `ThinkingPipeline._search_web` | передаёт в Wikipedia чистое имя концепции |
| `ThinkingPipeline._apply_web_result` | финальная проверка перед записью в KB и граф |
| `ThinkingPipeline._search_external_knowledge` | проверяет результат локального поиска по docstring |

### 1.3. Ручная чистка

`tools/clean_kb.py` использует те же правила, что и рантайм:

```
python tools/clean_kb.py            # dry-run
python tools/clean_kb.py --apply    # перезаписать файл
```

## 3. Тесты

Новый файл `tests/test_stage2_knowledge.py` — 36 тестов:

* все правила `check_entry` на реальных мусорных записях из baseline;
* `DEFAULT_KNOWLEDGE` и файл в репозитории проходят фильтр;
* `WebSearcher` не ходит в сеть на «?», `s_1`, `42`;
* страница-неоднозначность и нерелевантная статья не принимаются;
* запрос «что такое альфа» уходит в Wikipedia как «альфа»;
* `_apply_web_result` не пишет мусор и нормализует имя узла графа;
* `KnowledgeSubsystem` фильтрует load/save/add_definition.

Также обновлены фикстуры `tests/test_web_search.py`: раньше они использовали
запросы `test`, `X` и определения `"Y"`, которые теперь справедливо
считаются мусором.

Итог по затронутым модулям: **272 passed**.

## 4. Честные ограничения

* `Альфа` и `Малютка` — нормальные слова, поэтому они не в чёрном списке.
  Против них работает не список, а проверка релевантности: если статья
  не содержит слов запроса, она не сохраняется.
* Проверка релевантности — по точному вхождению слова, без морфологии.
  Возможны ложные отказы («мышление» ↔ «мыслить»). Это осознанный
  компромисс: лучше не получить знание, чем получить неверное.
* Смысловой мусор вроде `число 42` или `символ x` фильтр не ловит —
  это уже качество извлечения концептов, а не валидация записи.
